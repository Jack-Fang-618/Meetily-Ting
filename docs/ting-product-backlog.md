# Ting 产品讨论与待改清单

更新日期：2026-10-22（香港时间）

本文持续记录试用 Meetily 开发版时发现的产品调整事项。用于后续集中讨论和实施，不代表所列能力已经实现，也不授权现在展开全部改动。开发环境记录见 [ting-dev-setup.md](ting-dev-setup.md)。

## 已确认的产品方向

- 最终产品是 Ting：围绕音频转录、上下文辅助核验、人工确认，再按需总结。
- 学习旧 Ting 背后的目标和抽象，结合 Meetily 的实际架构设计；不预设复用旧 Ting 代码、页面或数据结构。
- 保留全本地运行能力，同时支持用户主动选择云端 STT 或 LLM。
- 保留原始音频与原始 ASR，区分 AI 建议和人工确认。上下文合理性不能代替音频证据。
- 当前先跑通开发版基本流程；以下产品改动暂缓，之后一起审议、实施。

## 待改事项

### 01 — 欢迎页与隐私文案

状态：已记录，待设计和实施。

当前欢迎页包含：

- `Welcome to Meetily`
- `Record. Transcribe. Summarize. All on your device.`
- `Your data never leaves your device`
- `Intelligent summaries & insights`
- `Works offline, no cloud required`
- `Takes less than 3 minutes`

用户指出：加入云端转录或总结后，不能继续无条件声称所有处理均在设备上、数据永不离开设备。

拟调整方向：

- 欢迎页逐步使用 Ting 产品名称，保留适当的 Meetily 开源归属及许可说明。
- 表达“支持全本地；云服务由用户选择”，避免绝对的数据不外传承诺。
- 在产品主线中体现转录、核验和人工确认；总结为可选后续步骤。
- 将“可离线工作”限定为已具备所需本地模型、组件的使用方式。
- 设置耗时受模型下载、网络与权限配置影响，重新评估“三分钟以内”的承诺。
- 最终文案、语言和布局尚未确定，不在云功能未实现时宣称已经支持。

验收要点：欢迎页、设置、关于页等相关位置的表述与实际行为一致。

源码线索：`frontend/src/components/onboarding/steps/WelcomeStep.tsx`、`frontend/src/components/About.tsx`。

### 02 — 首次设置按处理环节分别选择

状态：讨论方案，待确认交互和实现。

| 环节 | 拟提供选择 | 云端处理涉及的数据 |
| --- | --- | --- |
| STT 语音转录 | 本地 / 云端 | 音频及适配器实际需要的参数、上下文 |
| AI 核验 | 本地 / 云端 / 暂不启用 | 转录文本与用户选定的上下文；若涉及音频复核，须另外明确 |
| 总结 | 本地 / 云端 / 暂不启用 | 选定版本的转录文本及总结所需上下文 |

- 各环节独立配置，支持本地转录加云端总结等混合方式。
- 选择云端的用户，不应被强制要求下载不使用的本地模型。
- 用户应能暂缓配置可选环节，之后在设置中补充或更改。
- 具体供应商、模型、默认值与 API Key 管理方式，待架构审查后决定。

验收要点：纯本地、混合与云端路径均有清楚的设置过程；不把下载某个固定模型作为所有用户的必经步骤。

源码线索：`frontend/src/components/onboarding/steps/SetupOverviewStep.tsx`、`frontend/src/components/onboarding/steps/DownloadProgressStep.tsx`、`frontend/src/contexts/OnboardingContext.tsx`。

### 03 — 云端选择与数据流向说明

状态：原则已记录，具体交互待设计。

- 默认保留本地路径；云端处理必须由用户明确选择。
- 在选择云服务时说明服务商、发送的数据类型，以及该设置作用于哪些任务。
- 本地模型失败时，不得静默切换云服务。
- 不把云端模型输出自动视为经过人工确认的记录。
- 保留全本地模式，实际核查网络行为后再确定对外隐私承诺的范围。

验收要点：用户能够判断一次操作会不会发送音频、转录文本或上下文，以及发送给谁。

### 04 — Setup Overview 的快速开始路径

状态：用户确认方向，待设计和实施。

当前页面声称必须下载转录和总结模型，并把两个下载步骤作为开始使用的前提。未来应让用户选择下载本地模型或配置 API；总结可暂不启用。仅下载当前所选路径需要的模型。

配置 API 的具体字段、服务商兼容性校验、连接测试及密钥保存方式另行设计；不能假设支持聊天接口的服务也支持音频转录接口。尚未接入云 STT 前，不提前展示可用承诺。

验收要点：已配置可用云 STT 的用户，无需下载本地转录或总结模型即可开始转录；纯本地路径仍完整可用。

### 06 — 上下文输入与可复用的项目背景包

状态：用户确认希望做，暂不实施；命名及交互待设计。

当前观察：截图中的输入框标明供 AI summary 使用，示例为参会者、会议背景与目标。用户希望将其扩展为核验转录也可使用的上下文入口，减少每次重复打字。

目标：

- 保留文字输入，增加语音补充背景的入口。语音转成可编辑草稿，由用户检查后再作为上下文使用，避免口述识别错误成为事实。
- 可选择以前使用过的项目背景包（暂称 Context Pack）：项目背景、人员与机构名称、术语、缩写、语言习惯及已确认的相关信息。
- 同一项目的多次会议复用背景包，同时允许添加仅属于本次会议的补充说明。
- 背景包回答“这是什么项目、有哪些背景”；输出模板规定“结果如何组织”。两者是不同概念，不混成一个 Template 菜单。
- 用户能知道本次任务选中了哪些包，以及它们用于转录提示、AI 核验还是总结。是否给 STT 使用、如何适配需另行设计。

设计约束与建议：记录包的来源、版本、作用范围及每次处理实际使用的快照；AI 猜测不自动沉淀为背景事实，人工修改是否收录应由用户确认。背景只辅助判断，不能替代音频证据。

待定：包的创建与编辑入口、多个包冲突处理、项目归属方式、语音输入使用哪个 STT，以及包更新是否触发历史录音重处理。

验收要点：两次会议能复用同一背景包并保留各自补充内容；口述内容可检查修改；历史结果能追溯当时采用的上下文。

### 07 — 从总结面板扩展为转录核验工作台

状态：用户确认产品方向，布局和技术方案未定，暂不实施。

用户希望利用现有转录区和右侧总结区，形成一个能完成校验、回听、人工修改、再次交给 AI 处理的综合工作台。现有布局是候选承载位置，不代表已经决定把全部功能塞进一个面板。

目标流程：原始 ASR → AI 初审／整理稿 → 可追溯的自动修订与待核实项 → 用户回听、修改和反馈 → 按需重新核验 → 可选总结。

- 用户希望依据充分的高置信错误先由 AI 修正，低置信和存在歧义的内容反馈给用户处理。
- “高置信”的判定与自动应用策略仍需设计；LLM 自报置信度不能视为声学证据。所有自动修改必须保留原文、差异和来源，可回退；证据不足则标记，不猜写。
- 待核实项关联对应音频位置，支持反复回听；时间定位为估算时要明确说明。
- 用户可接受建议、手动改写、保留原文、暂缓处理，并补充说明或背景，让 AI 再处理指定问题或相关片段。
- 再处理不得静默覆盖人工确认内容，保留版本及本次反馈。具体锁定／冲突机制待设计。
- 区分原始转录、AI 修订、人工确认状态，以及可读性整理、总结等派生结果；不能把生成了新稿等同于全文已确认。
- 模型、语言和输出模板仍可配置，但核验规则与总结模板需分别表达。

界面澄清：截图中的 Auto 与总结语言选择有关；源码 `frontend/src/components/SummaryLanguageSettings.tsx` 明确 Auto 使用转录文本的主要语言。不能据此认定当前已有全文自动翻译功能。

验收要点：一个不确定片段可以完成“定位回听 → 用户修订／补充背景 → 再次核验”，全程可比较原文与修改，也能区分尚未确认的内容。

### 08 — 围绕总结对话，并可选联网搜索

状态：用户特别希望做，后续规划项，暂不实施。

目标：总结生成后仍可继续提问和讨论；除基于会议材料的讨论外，可按用户选择使用具有外部搜索能力的 AI，引入外部资料。

- 区分“只用会议材料回答”和“联网查资料”；云端 LLM 调用不自动代表启用网络搜索，两项能力分别配置和说明。
- 明确对话读取的是总结、选定转录版本、用户选择的片段，还是项目背景包，避免默认发送所有材料。
- 联网答案应区分会议中说过的内容、外部来源与模型推断，并提供可检查的来源；外部资料不自动写回转录或变成项目背景事实。
- 对话与总结关联使用的材料版本；核验结果更新后，如何刷新总结和对话上下文需另行设计。

待定：供应商与搜索工具、对话存储、上下文长度、版本更新方式、是否允许用户选择脱敏或摘录后发送。当前不承诺特定供应商具备联网能力。

验收要点：用户能仅基于本地材料对话，也能明确选择联网扩展；回答中的外部信息与原会议内容可区分。

### 09 — 外部处理告知与录音提醒

状态：用户明确重视，保留并扩展这一设计方向。

用户反馈：录音时出现“是否已经通知所有参会者正在录音”的提醒，这个功能很好，应保留。此为用户观察，尚未审查其全部触发条件。

- 开始录音时保留参与者告知提醒。提醒本身不等于已经获得所有人的同意。
- 使用外部 API 前，应清楚告知即将发送什么、发送给哪个服务、用于什么功能，并给出继续或取消的选择。
- 录音告知、云端处理选择、联网搜索选择分别处理，不能以同意录音代替同意向外部发送会议材料。
- 搜索查询本身也可能暴露项目名称、人物或敏感问题；外部 LLM 和搜索服务可能是不同接收方，要分别说明。
- 语音补充背景若走云端，同样需要清晰说明音频去向。
- 告知应发生在传输前，而不是发出后才弹通知。如何保存选择、何时再次提示，待交互设计，避免机械重复打扰。
- 不对第三方的数据留存或训练用途作未经核实的承诺。

验收要点：用户可以在传输前了解并取消外部处理；纯本地模式不因对话或失败重试而静默联网；录音提醒得到保留。
