# 转录输入限制统一管理

唯一配置：`tools/transcription-input-limits.json`。Whisper（含 BuzzASR）、Parakeet、Qwen（含 0.6B/1.7B 及粤语微调版）分别继承各自运行引擎的策略。

目前统一要求 16 kHz、单声道、有限 f32 数值；Whisper/Qwen 最长推理窗口 400000 样本（25 秒），Parakeet 为 240000 样本（15 秒），最短窗口 1600 样本。这些时长是保守的应用处理窗口，不是各模型理论上下文上限。当前音频管线负责解码、混音和重采样；原始 Vec 本身无法证明采样率或声道，调用者必须遵守格式约定。

Rust input_policy::transcribe_bounded 在引擎公共入口验证并分段，覆盖实时录音、导入、重新转录及直接命令调用。Whisper/Qwen 在最后 5 秒、Parakeet 在最后 10 秒内选择能量最低的 20 ms 边界，每个样本恰好覆盖一次，不超上限。短尾段补零，不再直接丢弃。NaN/Inf 在任何推理之前拒绝；模型失败向上返回，不静默跳过。

导入和重新转录用同一个范围算法保留各段的起止时间。实时录音仍沿用外层 VAD 段时间戳；这项改动没有实现逐词对齐，也没有限制上游 VAD 的等待时间。

Python Qwen worker 从同一 JSON 读取规则，作为独立调用时的保护层。Rust 已切好的窗口不会再次切分。Python 仍保留静音过滤。

新增引擎必须登记自己的策略并通过公共分段入口；同一引擎的新模型先验证兼容性。如需不同限制，应新增独立策略并在适配器中明确选择，不能假定沿用安全。修改采样率/声道需要同时适配音频归一化，本注册表目前拒绝其他格式。

验证：三个引擎策略均有模拟推理测试，覆盖此前 982240、2118880、1193920 样本报错长度、空输入、短尾段、静音边界、NaN/Inf、未知策略、推理中途失败。Python 有对应边界及尾段测试。这不等于所有模型权重都经过实机准确率测试。

2026-11-10 Parakeet 漏段回归：现有 INT8 权重在 20–25 秒窗口中会漏掉整个句子，独立 onnx-asr 参考实现也复现；15 秒上限/10 秒寻静音范围恢复本次八段英语内容。该值是已验证的接入策略，不是模型理论上限或所有长音频准确率保证。

Parakeet 的文件导入、重新转录统一调用 file_segments_with_progress，保留所有样本及绝对时间，不使用二值 VAD 提前丢掉轻声内容。其他 Provider 保留原有 VAD 路径。实时采集的上游 VAD 本轮不变；实时与文件识别都受引擎 15 秒窗口限制。文件包含长静音时可能多做一些推理，这是优先避免漏句的取舍。
