# Parakeet 长录音漏段：诊断、修复与复测

## 诊断

旧基线 `f283c78`。测试文件 `speech-test-pack-v1/05-Long-Regression/English-over-60s.wav`，74.04 秒、1,184,640 个 16 kHz 单声道样本。

1. 旧 25 秒规则实际分为 0–20.02、20.02–42.88、42.88–66.10、66.10–74.04 秒。范围连续、全覆盖，没有丢样本，但第一、第三个窗口各漏掉一整句。
2. 从这个长 WAV 原样切回八个片段，均能识别，排除拼接 PCM16 编码把原声音频破坏的解释。按片段均衡音量的控制试验仍漏同样两句。
3. 绕过 Ting 引擎分段，把全长 74 秒直接送入同一 ParakeetModel，会漏掉更后面的内容。不是拼接文本时丢掉结果。
4. 使用独立 `onnx-asr 0.12.0 / onnxruntime 1.31.1`，加载相同 encoder/decoder 权重，正确设置 128 维 mel 特征，仍复现同样窗口漏句。说明现有 INT8 权重/推理路径对较长输入不稳定，不是 Ting 专有 Rust 文本合并错误。本轮没有与原始 NeMo FP32 权重对比，**不能进一步断言根因一定是量化或某个具体 ONNX 算子**。
5. 文件导入还存在另一层损失：原 2000 ms Silero VAD 在这份音量差异很大的拼接录音中，会拒绝轻声片段、裁掉句首。换短窗口不能恢复 VAD 已经删除的声音。

## 改动

- 统一输入注册表中，Parakeet 上限从 25 秒收紧为 15 秒，在末尾 10 秒寻找最低能量的 20 ms 切点。其他引擎窗口不变。这是针对现有模型的应用策略，不是理论上下文上限。
- 文件导入和重新转录调用同一个 `file_segments_with_progress`。Parakeet 分支保留全部样本与绝对时间，不用二值 VAD 把轻声片段提前排除；Whisper/Qwen 继续使用原路径。
- 模型公共入口仍再次限制输入，覆盖直接调用和实时上游给出的较长片段。实时采集的上游 VAD 本次未改，不声称实时轻声漏检也已经修复。
- 文件里的长静音也会进入推理，可能增加耗时；本次实机验证纯静音输出为空。没有加重叠窗口或文本去重，不会靠删除重复词掩盖样本重叠。

## 验证

- 254 项 Rust 单元测试通过；新增样本完整覆盖、时间戳连续、取消、非有限数值输入的回归。
- 显式实机内容回归通过：直接引擎输出与导入共用的分段路径输出相同；八个句子各自的关键短语均出现一次；纯静音无文本。替代原来仅检查“结果非空”的弱断言。
- 相同 30 文件重跑 Parakeet，74 秒英语 WER 从 **28.4% → 3.2%**，两段丢失内容恢复；八个短英语文件 WER 仍为 **3.2%**。
- 额外控制：把八段倒序拼接，八个关键短语各出现一次；把整组重复两遍得到 148.08 秒文件，各出现两次，没有漏段或重复加入。
- 这些检查验证引擎和文件分段函数，不是原生 GUI 自动点击，也不验证 DB 写入流程的所有行为。没有声称所有长会议录音都不会再出问题。

诊断产物：`experiments/parakeet-gap-fix/`，含旧路径、参考实现、短片段/音量控制、15 秒策略、额外长文件结果。重跑结果：`experiments/speech-comparison-after-fix-2026-11-10/`。原始对比保留，未覆盖。

## 后续评测

本次 30 文件为开发样本，非完整 benchmark。下一轮可扩大 FLEURS 测试子集和自然长英语录音；粤英口语须遵守 WSYue 的 NC 许可。新模型和分段策略应分别验证短句、长句、多说话人、长静音、轻声和真实会议；不能以几个关键词或单次成功作为全量稳定性的证明。
