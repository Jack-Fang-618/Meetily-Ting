# 本地模型准备进度与英文界面

- 根因：Hugging Face 下载条原来写到 stderr，前端只收到“Downloading …”阶段消息，并一直使用无百分比的动画；并非下载进度已经接到界面。
- Python 准备程序通过 JSON-lines 输出真实文件就绪字节（包含缓存）、总字节、百分比、网络传输速度。总大小来自已固定的 huggingface-hub 2.2.0 dry-run 元数据，Xet/HTTP 更新由库的字节计数器提供。元数据大小未知时不编造百分比。
- 下载、合并、转换、模型加载验证分别显示阶段；后台每秒发一次心跳和已用时间。连续 15 秒没有字节更新时说明可能等待网络/写入缓存，不直接宣布“卡死”。转换阶段没有百分比，保留取消入口。
- 进度同时保存在 Rust 状态并发送事件，切走设置页再回来仍可读取。新的 stdout 协议兼容旧纯文本输出；日志与错误继续保留。
- 转换库重定向 stdout 时，心跳仍使用预先捕获的协议输出流，避免转换时进度再次消失。
- 模型选择页、导入/重新转录选择器中的新增模型名称、说明和进度文案统一英文。标签单独放在前端；**未改已安装标记中参与校验的 catalog 元数据**，不会因为翻译而把模型误判为未安装。
- 验证：真实小文件下载从 0 到 100% 的协议冒烟测试；缓存/断点计数、未知大小、阶段切换、无终端计数、stdout 重定向单元测试；Rust 协议解析与范围校验；模型卡片百分比/详情呈现测试。TypeScript 与生产构建通过，前端 54 项测试通过。
- 没有取消或重启用户当时正在进行的 BuzzASR 下载；其完成后已成功加载实测。UI/Rust 改动需重新启动开发版生效，本次没有强行重启正在打开的应用。
